## 1. 지금 상태와 목표

게임의 아이콘·장면 그림은 **거의 전부 코드로 그린 자리표시(더미)** 다.
완성된 손그림은 유물 노드 9장 · 마나/마릿수 기호 2장 · 전투 배경 5장뿐이다.

- 만들 것: **약 330장** (P0 4 · P1 236 · P2 91 · 선택 P3 52)
- 방식: **같은 경로에 같은 파일명으로 덮어쓴다.** 새로 만드는 파일은 ImageSpecs 가 경로를 정해 준 것만.
- 스타일: **픽셀아트** — 기준은 이미 있는 완성본 3장 (3장 참고)

## 2. 절대 규칙

1. **전부 도트(픽셀아트)로 그린다.** 부드러운 일러스트·유화풍·3D 렌더·사진은 한 장도 섞지 않는다 — 게임 안 유닛과 배경이 전부 도트라 한 장만 매끈해도 그 칸만 붕 뜬다. 제작 방식은 3.2, 판정은 6.1(색 수·가장자리 번짐).
2. **아이콘은 4장씩 한 시트로 만든다** (5.1). 한 장씩 따로 만들면 광원·외곽선·팔레트가 장마다 흔들린다.
3. **경로·파일명·`.meta` 를 바꾸지 않는다.** PNG 바이트만 교체한다. `.meta` 의 GUID 가 게임 안 모든 참조의 전부다 — 파일을 지웠다 새로 만들면 참조가 끊긴다.
4. **`.meta` 파일을 새로 만들거나 수정하지 않는다.** 새 PNG 를 넣으면 유니티가 알아서 만든다.
5. **그림 안에 글자·숫자를 넣지 않는다.** 게임은 10개 언어로 번역된다. 단계 표시는 점(핍)으로.
6. **워터마크 금지 — 특히 오른쪽 아래 반짝이(✦) 마크.** 지금 `Assets/Resources/Icon/Icon.png` 오른쪽 아래에 이미지 생성 도구의 마크가 박혀 있다. 한 장씩 오른쪽 아래 모서리를 확대해 확인하고 지운다.
7. **가장자리가 번지면 안 된다.** 외곽선은 또렷하게 — 기준 완성본(`node_soul_urn.png`)은 반투명 픽셀이 39% 수준이다. 그보다 훨씬 부옇게 퍼지면 픽셀아트로 안 읽힌다 (검사기가 50% 를 넘으면 경고한다).
8. **이미 완성된 것은 건드리지 않는다** — 9장의 유물 노드(256px), `Icons/InGame/icon_mana·icon_summon_count`, `BG/BG1~BG5`, `MonsterSheets/*`, `FX/*`.
9. **쓰지 않는 그림은 만들지 않는다** (7장 목록). 지우지도 않는다.
10. 규격(크기·격자)은 4장 표를 따른다. 임의로 바꾸지 않는다.

### 3.2 제작 방식 — 논리 격자 ×4

모델에 128px 을 직접 요구하면 뭉갠다. **작은 격자로 설계하고 정수배로 키운다.**

| 최종 크기 | 논리 격자 | 확대 |
|---|---|---|
| 128×128 | 32×32 | ×4 nearest |
| 256×256 | 64×64 | ×4 nearest |
| 1920×1080 | 480×270 | ×4 nearest |

- 생성 → 논리 격자로 다운샘플(팔레트 양자화) → 손질 → 확대. 형태는 논리 격자 위에서 읽혀야 한다.
- ⚠ **한 픽셀도 어긋나지 않는 완전한 격자를 요구하지는 않는다** — 기준 완성본(`node_soul_urn`)도 가장자리에 부드러운 픽셀이 섞여 있다. 요구하는 것은 **또렷한 외곽선과 좁은 팔레트**지 격자의 순수함이 아니다.
- 외곽선: 논리 1px, 주조색보다 훨씬 어두운 색(`#1B1522` 근처, 순흑 금지).
- 광원: **좌상단 하나.** 수십 장이 한 화면에 같이 뜬다 — 광원이 흔들리면 잡동사니가 된다.
- 디더링은 넓은 면에만 최소로. 여백은 128 기준 사방 8~12px (주제가 가장자리에 닿지 않게).

### 3.3 의미 색

| 의미 | 색 |
|---|---|
| 피해·공격 | 주황 → 적 |
| 화염 | 주황 · 노랑 |
| 회복·재생 | 초록 |
| 독·역병 | 연두 · 독초록 + 보라 기포 |
| 냉기·둔화 | 청록 · 빙청 |
| 방어·강철 | 청회 · 강철 |
| 마나·마법 | 보라 · 청보라 |
| 소환·언데드 | 뼈색 + 보라 |
| 골드·경제 | 금 · 호박 |
| 속도 | 하늘색 + 흰 속도선 |

⚠ **동·은·금(시너지 단계) 색은 아이콘에 쓰지 않는다** — 게임 UI 가 칩 바탕에 칠한다. 아이콘은 제 색을 갖고, 꺼진 상태는 UI 가 알파만 낮춘다.

## 5. 작업 순서 (우선순위)

한 계열을 끝낼 때마다 6장의 검수를 하고 **계열 단위로 제출**한다. 한 번에 330장을 쏟지 않는다.

**계열마다 이 순서로 한다**
1. 그 계열의 ImageSpecs 를 끝까지 읽는다 (특히 '구분' — 다른 그림과 닮으면 안 되는 짝).
2. **첫 시트 한 장(아이콘 4개)** 을 먼저 만들어 보여 준다 — 틀·판 색·외곽선·광원을 여기서 고정한다. 사용자 확인 뒤 나머지.
3. 4장씩(5.1) 끝까지 만든다.
4. 6장 검수 → 제출.

### 5.1 아이콘은 4장씩 한 시트로 (2×2)

**아이콘 계열은 한 번에 한 장씩 만들지 않는다.** 4개를 **한 이미지 안 2×2** 로 같이 그린 뒤 잘라 낸다.

- **왜** — 한 장씩 만들면 같은 계열인데도 광원 방향·외곽선 두께·판 색·채도가 장마다 흔들린다. 한 시트 안에서 그리면 네 장이 **같은 붓**으로 나온다. 화면에서 이 넷은 실제로 나란히 뜬다.
- **시트 규격**
  | 최종 크기 | 시트 | 한 칸 | 자른 뒤 |
  |---|---|---|---|
  | 128 아이콘 | 1024×1024 | 512×512 | 각 칸을 128 로 축소 |
  | 256 아이콘 | 2048×2048 | 1024×1024 | 각 칸을 256 로 축소 |
  - 칸과 칸 사이에 **선·여백·프레임을 그리지 않는다.** 칸 경계에 그림이 걸치면 잘린 조각이 이웃 파일에 남는다 (검사기가 경고한다).
  - 배경은 **완전 투명** — 시트 배경을 색으로 채우면 잘라 낸 아이콘마다 그 색 판이 따라붙는다. (판이 필요한 계열은 판을 **칸 안에** 그린다.)
  - 자를 때는 정확히 1/2 지점에서 자른다. 축소는 마지막에 한 번만 (3.2).
- **무엇을 한 시트에 묶나** — 아무거나 넷이 아니다. 우선순위:
  1. **ImageSpecs 의 '구분' 에서 서로 닮으면 안 된다고 적힌 짝** — 한 시트에 넣으면 그리는 동안 차이가 눈에 보인다.
  2. **한 벌로 읽혀야 하는 묶음** — 단계 I·II·III(핍만 다름), 각성판과 그 원본, 마왕성 체력 4노드처럼 점점 커지는 계열.
  3. 나머지는 ImageSpecs 에 적힌 순서대로 넷씩.
  - ⚠ **계열을 섞지 않는다.** 시너지와 종족 패시브를 한 시트에 넣으면 틀이 섞인다.
- **넷 중 하나만 틀렸으면** 그 시트를 다시 만들거나 그 칸만 고친다 — 나머지 셋을 이미 저장했으면 **덮어쓰지 않는다** (통과한 것을 다시 굴리면 계열이 또 흔들린다).
- **시트 원본은 커밋하지 않는다.** 작업 폴더에만 두고, 저장소에는 잘라 낸 개별 PNG 만 넣는다.

⚠ **시트로 만들지 않는 것** — 장면 그림 19장(1920×1080, `07`)과 브랜드 4장(`00`)은 **한 장씩** 만든다. 크기도 구도도 제각각이라 묶을 이유가 없다.

## 6. 검수 — 제출 전에 반드시

### 6.1 기계 검사

```bash
python Docs/tools/verify_images.py            # 전체
python Docs/tools/verify_images.py Synergies  # 폴더 하나만
```

검사 항목: 크기 · RGBA · 완전 투명/불투명 · 가장자리 번짐(기준 완성본 대비) · 색 수(사진·3D 렌더는 너무 많고, 자리표시 더미는 너무 적다) · **시트에서 어긋나게 잘렸는지**(투명 배경 계열의 가장자리) · 오른쪽 아래 워터마크 의심 얼룩.
⚠ 이 검사기는 **규격만** 본다 — 무엇이 그려졌는지는 6.2 로 눈으로 본다.
**에러가 하나라도 남아 있으면 제출하지 않는다.**
⚠ 시작할 때 한 번 돌려 보면 **남은 일 목록이 그대로 나온다** — 2026-09-23 기준 에러 315개가 곧 "바꿔야 할 파일" 이고, 통과 9개가 완성본이다.

### 6.2 눈 검수 — 표시 크기로 본다

```bash
python Docs/tools/verify_images.py Synergies --sheet   # 계열 시트 PNG 를 만든다
```

시트를 보고 확인할 것 — 4장의 '화면 표시' 크기에서:
- 무엇인지 읽히나 (이름을 몰라도)
- 옆 그림과 헷갈리지 않나
- 광원·외곽선·판 색이 계열 안에서 같나
- ImageSpecs 의 '구분' 에 적힌 짝과 안 닮았나

**128px 에서 예쁜지가 아니라 48px 에서 무엇인지 읽히는지가 합격선이다.**

| 완성본 (2장 규칙 8) | 이미 손그림이다 |

## 8. 범위 밖 — 당신이 하지 않는 일 (사용자가 유니티에서 처리)

아래는 **유니티 C# / 에디터 작업**이다. 건드리지 말고, 제출할 때 "이것들이 필요하다" 고 한 줄로 알려만 준다.

| 무엇 | 왜 필요한가 |
|---|---|
| 아이콘 생성기가 손그림을 덮어쓰지 않게 막기 | 지금 유니티 도구를 다시 돌리면 **넣은 그림이 더미로 되돌아간다** |
| 임포트 설정(`maxTextureSize`) 상향 | 128/256 로 키운 그림이 임포트 단계에서 다시 줄어든다 |
| 시설 장면(`Scenes/Facilities/`) 을 화면에 연결 | 지금 코드는 갈림길 카드 그림을 늘려 쓰고 있다 |
| 새 스킬 그림 3장(`skill_mana_burst · skill_flame_aura · skill_slime_mend`) 키 연결 | 지금은 남의 그림을 빌려 쓴다 |
| 장비 개별 아이콘(P3) 을 읽게 하기 | 지금은 부위 그림 8장을 나눠 쓴다 |
| 스프라이트 아틀라스 다시 굽기 | 안 하면 화면에 빈 칸으로 뜬다 |

⚠ 그래서 **당신이 새로 만드는 파일(시설 장면 4 · 스킬 3 · 장비 52)은 경로에 놓아만 두면 된다.** 게임에 안 보이는 것은 정상이고, 연결은 사용자가 한다.

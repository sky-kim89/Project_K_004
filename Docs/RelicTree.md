## 시스템 효과가 실제로 걸리는 곳

스탯 노드는 `RelicTreeApplier.ApplyToMonsterStat` 이 `UnitStat` 에 얹는다.
그 밖의 것은 각 규칙 클래스가 `GetSystemValue` 로 물어본다 —
**효과를 새로 만들면 읽는 쪽도 반드시 함께 만들 것.** 실패가 조용하다.

| 효과 | 훅 지점 |
|---|---|
| 최대 마나 · 소환 비용 · 마릿수 · 배출 간격 | `RunPerkRule` (특성과 같은 자리) |
| 스테이지 마나 회복 | `ManaRegenRule.RawFor` |
| 과부하 계수 | `SummonerVigorRule.OverloadStepFor` |
| 소환사 평타 비율 | `SummonerStrikeRule.Build` |
| 시너지 문턱 · 중첩 | `MonsterSynergyRule.StepsOf` / `StackBonus` |
| 마왕성 체력 | `SummonerData.MaxCoreHp` |
| 야영지 회복 | `RunNodeFlow.CampHeal` |
| 카드 3택 · 특성 선택지 | `CardRewardPicker.CurrentChoiceCount` / `RunBootstrap.OfferPerk` |
| 새 카드 시작 레벨 | `SummonDeckData.Acquire` |
| 종족 패시브 · 분열체 · 사망 효과 | `SpeciesPassiveRuntime` (`PassivePower` / `DerivedScale` / `DeathPower`) |
| 장비 상자 · 장비 스탯 | `RunBootstrap.GrantGearBox` / `MonsterGearRule` |
| 런 골드 · 환생 포인트 | `RunGoldRule.Grant` / `ReincarnationData.PreviewPoints` |
| 용사 약화 | `RelicTreeApplier.ApplyEnemyWeaken` ← `GeneralRuntimeBridge.Initialize` |

## 손댈 때 지켜야 하는 것

- **몬스터 스탯 노드는 `AbilityTarget.Unit_Monster` 다.** `All` 로 두면 같은 노드가
  장수 경로(`ApplyToGeneralStat`)에도 걸려 **적까지 강화된다.**
- **적용은 `MonsterStatComposer` ⑥-b 한 곳뿐이다** (특성 뒤 · 장비 앞).
  비율끼리는 순서가 값을 바꾸므로 자리를 옮기지 말 것.
- **좌표 규칙** — 같은 x 면 `dy ≥ 2`, 같은 y 면 `dx ≥ 2`. 노드 카드가 겹친다. 대각선은 자유.
- **마왕의 위엄은 %p 가산이다.** 비율로 곱하면 잡병(25%)만 크게 오르고 보스(1%)는
  티가 안 나, 보스를 잡는 유물이 되기 전에 잡병 청소기가 된다.
- **조율은 동 문턱만 내린다.** 은·금까지 내리면 7종 계열의 금(7)이 5로 떨어져
  확장 편성 없이 닿는다 — 금이 덱 칸을 압박하는 설계가 사라진다.
- **조기 성장은 특성 '속성'과 더해서 한 번에 잡는다.** 따로 적용하면 둘 다 가졌을 때
  뒤엣것이 앞엣것을 덮어써 하나가 조용히 무효가 된다.
- **아이콘 파일명은 노드 이름에서 나온다** (`RelicIconKey`). 이름을 바꾸면 다시 구울 것.
- `RelicSystemEffect` **1~12 는 원작 잔재**다. 원작 화면이 아직 참조해 남겨 뒀을 뿐이니
  새 노드에 쓰지 말 것 (4·7·8·10 만 이 게임에서 살아 있다).
